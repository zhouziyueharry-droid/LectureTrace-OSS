# 步进式问答 Agent

`stepwise_qa` 是 LectureTrace 中基于 LangGraph 的课程问答实现。它会读取已有的大纲、短索引、字幕和幻灯片证据，再根据问题类型组织回答。运行方式标识为 `stepwise_qa`，设置 API 为 `/api/stepwise-qa`；独立设置保存在数据库键 `stepwise_qa_settings` 中。

## 一轮问答概览

完整节点与分支见 [工作流图](WORKFLOW.md)。概括来说：

1. API 层接收提问，检查问题和拓展选项参数，并取得会话锁。
2. Chat adapter 读取课程上下文和历史对话，构造 `TutorState`，再运行 `TUTOR_GRAPH`。
3. LLM 判断任务类型，再定位并展开课程证据；需要时最多补检索一次。
4. 简单概念/疑难问题在首轮找到证据后走快速路径；复杂任务走证据评估和教学审阅，最多修订一次。
5. Chat adapter 规范引用、检查有效证据 ID；若引用无效会尝试修复一次，然后保存回答和后续选项。

## 各模块职责

| 文件 | 职责 |
| --- | --- |
| [`api.py`](api.py) | 独立模型设置 API：读取/更新步进式 Agent 的服务商、模型、API 地址、Key、思考强度、输出上限和语言；提供连接测试。 |
| [`settings.py`](settings.py) | 保存配置默认值、校验配置、读取后端数据库中的 Agent 配置。 |
| [`llm.py`](llm.py) | 按配置调用 OpenAI 兼容 Chat Completions 接口；提供普通文本与 JSON Schema 结构化输出，并归一化 API 错误。 |
| [`state.py`](state.py) | LangGraph 单轮状态定义，包括问题、意图、证据、回答、审阅结果和拓展选项。 |
| [`pedagogy.py`](pedagogy.py) | 提供各类问题对应的课程讲解计划；规则分类仅作为 LLM 分类失败时的兜底。 |
| [`schemas.py`](schemas.py) | 定义任务分类、证据评估、回答草稿、拓展选项、审阅意见和修订答案的数据结构。 |
| [`graph.py`](graph.py) | LangGraph 节点、课程证据评估、教学提示、回答草拟、审阅与一次性修订逻辑。 |
| [`chat.py`](chat.py) | 把问答请求接入图，向前端发送进度，校验/修复引用，持久化回答和拓展按钮。 |

相关的上游路由在 `backend/app/qa/chat.py`：当问答运行方式配置为 `stepwise_qa` 时，它把请求转发到本包。

## 详细流程

### 1. 请求与上下文准备

`chat.ask()` 检查空问题、附件/大纲编辑限制、拓展动作 ID 和来源范围，并取得课程会话锁。随后 `_ask_locked()`：

- 用 `context.build_context()` 读取课程证据、课程大纲和短索引；
- 读取可用历史对话和历史答案引用；
- 将问题、选中的拓展方向、课程上下文和历史记录放进 `TutorState`；
- 插入用户消息并开始运行 LangGraph。

### 2. 意图识别和教学计划

`_analysis_node()` 先让 LLM 根据本轮请求判断任务类型（概念、疑难、公式、例题、比较、表格、总结或开放任务），再由 `plan_for()` 选择对应教学计划。如果 LLM 分类调用或结构化解析失败，才回退到 `pedagogy.classify()` 的关键词规则。用户点击拓展按钮时，分类器会分析按钮对应的完整 `learning_prompt`，动作 ID 也会作为提示。

分类使用一个只含单一枚举字段的小型结构化结果，并关闭分类重试；失败会直接走关键词兜底，不阻断回答。`plan_for()` 提供代码维护的教学计划，不额外发起需求澄清对话。

### 3. 定位和读取课程证据

`_retrieve_node()` 根据问题类型构造定位请求，模型从短索引中挑出需要的讲解片段、幻灯片/出现或无幻灯片时段 ID。`context.expand()` 再展开讲解原文与所需截图。

- 普通知识点和课程拓展会围绕当前问题定位证据。
- 开放型课程任务会要求定位多个课程主题的代表材料，而不是只找一个关键词。
- 用户明确选择课外补充时，通常跳过课程检索；但被识别为课程相关的开放任务仍会检索课程，以支持答案出处。

简单概念/疑难问题首轮找到证据后跳过独立证据评估；若首轮没有找到证据，则仍进入评估和补充检索。

### 4. 证据充分性检查与补充检索

`_assess_node()` 判断复杂任务的课程证据能否支持回答。开放任务还会把课程大纲和短索引纳入评估，因为它们包含可引用的证据 ID。简单问题未找到首轮证据时也会进入评估；课外补充分支跳过课程证据评估。

若证据不足且评估器给出 `missing_query`，图会用它再检索一次。`MAX_RETRIEVAL_ROUNDS = 2` 表示总共最多两轮定位（首次加一次补充），不会无限搜索。达到上限后进入回答阶段，并要求指出仍缺少的资料。

### 5. 组织和生成回答

`_plan_node()` 固定当前教学计划。`_draft_node()` 通过 JSON Schema 结构化输出一次生成：

- `answer`：面向学生的回答；
- `self_review`：内部自检，检查术语、逻辑跳步和可能的疑问；
- `followups`：1–3 个可点击拓展方向，并附范围和候选课程证据 ID。

普通概念回答以短核心回应和必要的一步解释为目标；整课总结先给主线和最多 5 个核心节点；用户明确要求表格、公式或例题时优先完成该形式，不套固定双层模板。每轮还会提供“太复杂？通俗点”选项，点击后按“通俗解释（仅供理解参考）”和“课内简洁解释（依据课程内容）”两个短小节重答，优先用贴切的生活比喻解释逻辑。开放任务按请求的数量/格式完整交付。回答生成使用设置中的输出上限；普通回答的简洁程度由提示控制，而不是隐藏的代码上限。

### 6. 教学审阅和修订

`_review_node()` 使用另一条结构化调用检查复杂任务的回答是否直接、清楚、证据匹配；开放任务还检查是否完成数量/格式要求。简单概念/疑难问题跳过审阅调用。复杂任务发现问题时 `_revise_node()` 最多修订一次，并以 `TutorRevision` 结构约束最终输出仅含答案正文，避免把审阅或修订说明泄漏给学生。

如果审阅通过，或一次修订额度用完，图就结束。审阅和修订调用也会增加响应时间和模型 API 用量。

### 7. 引用校验、持久化和前端按钮

图结束后，`chat.py` 会：

1. 规范化答案里的引用格式，并在明确选择课外范围时加来源标记；括号中的证据 ID 组和讲解片段编号范围也会规范成可解析引用；
2. 只允许引用本轮短索引/展开证据以及历史有效引用中的 ID；
3. 如发现无效 ID，调用一次引用修复；修复后仍无效则将回答标记为失败；
4. 保存答案、引用和拓展选项；
5. 将模型选项限制为最多三项，过滤不在允许集合中的证据 ID，并在有课程证据时添加“放回课程整体看”按钮。

前端只负责显示回答、引用跳转、进度和拓展按钮；点击拓展会创建新一轮问答，并把原问题、选中方向及来源范围一并传回。

## 已知不足
- 课程检索最多两轮，开放任务证据覆盖不足时只能给出有依据的部分并说明缺口。
- 快速路径仅适用于首轮找到证据的概念/疑难问题；它跳过单独证据评估和教学审阅，但仍校验答案引用。证据不足时会进入完整评估流程，会让回答速度缓慢。
- Deepseek 测试时偶尔有返回的json解析失败的情况，需要重试结果生成。
- JSON Schema 能保证字段形状，不能完全保证模型内容正确；引用校验会拦截不在允许集合里的 ID。
- “通俗解释”是模型对课程概念的直觉化转述，不是教师原话；课程解释仍以实际课程证据为准。
- 使用体验大抵还是不如MCP。
