# 图片定位与按单元渐进读取

## 需求与决策

2026-11-08：用户授权把图片匹配做成 MCP 工具，并明确图片工具负责定位视频时间；时间定位到现有切分单元，Agent 先看简介，再按用户问题决定是否读取讲解或截图。不使用 embedding，不重跑 ASR、不调用付费模型。

## 现状

`S012` 是去重后的画面，`S012.1` 是一次连续出现（section），其 `t_ids` 指向分配好的全部转写片段。重复出现应保持独立；单元不是新的语义切分。网页问答已有短索引/按需展开。MCP 的目录只有时间和 ID，`read_evidence(S012.1)` 读取的是摘要，缺少时间定位及完整单元读取接口。

## 本轮契约

- `locate_slide(video_id, image_base64, offset=0)`：指定视频内，SIFT、ratio test、RANSAC 几何校验定位 PNG/JPEG 页面。返回候选画面、出现单元和时间，以及匹配诊断；不附截图、摘要或转写，不宣称候选为精确证明。匹配所有已记录的截图变体，缺失图片明确计数；结果分页。
- `get_video_units(video_id, version, timestamp, offset=0)`：按显示时间或已分配语音时间找单元，返回标题、已有摘要、摘要缺失/截断状态、显示和讲解边界及读取入口；不附原文或图片。区间左闭右开，无匹配则为空，不自动吸附附近单元。
- `read_video_unit(video_id, version, unit_id, text_offset=0)`：按该单元完整的 `t_ids` 读取转写，保留来源 ID 和时间，超过传输限制显式续读。图片沿用 `view_slide`。
- 原五个工具保留契约。新版 `get_video_context` 的 timeline 增加与时间查询相同的单元简介。
- 图片输入为标准 JSON base64，客户端编码图片；不允许 URL 下载或任意服务器文件路径。请求/字节/像素受限，图片不落盘。CPU 特征用有界进程内缓存，不写课程数据库。输入图片是客户端明确提供给服务器的内容，不能假定服务器能看到聊天附件。

## 验收

合成图验证缩放、透视、批注、无关图、空白图、相同页重复出现；协议验证三段读取、摘要不含转写、非连续 T 成员完整读取、跨页边界、缺失摘要、版本过期、分页、图片输入上限及路径逃逸。真实课程只读验证完整链路，记录冷/热查询耗时与数据未变。真实 PPT 匹配在取得具体文件后验证，不把自图变换测试当成原课件验收。
