# 标准 MCP 只读视频工具

## 背景与问题

用户希望在当前 AI 客户端直接读取 LectureTrace 视频资料，并明确要求兼容其他支持 MCP 的客户端。网页的 CourseWorkspace 包含工作区、笔记迁移和读取日志副作用，不能直接实例化作为只读服务。已有 HTTP API 也不是 MCP 协议。

## 已讨论方案

- 使用官方 Python MCP SDK，提供 Streamable HTTP 和 stdio；不依赖 Codex app-server、登录或私有结果格式。
- HTTP 与网页共用 FastAPI 进程、SQLite 和 DATA_DIR；stdio 仅打开已有数据库、读取产物，不启动 runner。
- 首版只开放 list_videos、get_video_context、search_video、read_evidence、view_slide。无上传、重跑、写笔记、外部模型调用。
- 提取共享证据读取逻辑；网页保留原有读取日志与引用验证。
- HTTP 默认禁用（未配置 token），启用后需要 bearer token，校验 Host/Origin，仅用于本机；stdio 由本机进程权限控制。
- 返回有边界、可分页的文本/JSON 与标准 image 内容；保留视频 ID、证据版本和来源。外部客户端自行生成的回答不宣称经过网页引用校验。

## 验证计划

共享查询与既有问答回归；标准客户端的 HTTP/stdio 握手、工具发现、错误、文本、图片；路径越界、凭证拒绝、版本过期、分页与无写入验证；真实课程只读协议检查。真实模型调用另行决定。

## 评审记录

用户已要求直接实现以便试用，并明确接口应通用。本轮按以上只读范围实施；新视频处理是后续范围。
